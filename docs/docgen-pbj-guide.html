Before You Start (Every Time)

  • Log in to the DCFG portal (dcfg.powerappsportals.com)
  • Customer must exist — if new, you'll create them in the wizard
  • Vendor must exist — if not, add via Admin > Vendors first
  • Location must exist — if not, add via Locations screen or in wizard
  • Template must be active — check Admin > Templates if generation fails
  • You'll need: customer name, vendor name, location, start/end dates, fee amount, description of work
WORK ORDERS & AMENDMENTS

All use the New Contract Wizard — same 5 steps, different doc type selection at Step 2.

Decades Work Order Work Order Decades_Work_Order.docx
Go to Contracts > New > Work Order
Or click + New button on contracts list, pick "Work Order"
Step 1 — Pick the Customer
Search by name. Select. Their programs and locations load automatically.
Family is auto-detected — Decades customers get Decades templates.
Step 2 — Document Type
  • Type: Work Order (already selected)
  • Pick the Location (property)
  • Pick the Vendor
  • Set Start Date and End Date
  • Enter Description of Work
Step 3 — Contractor & Signer
Vendor details auto-fill from vendor record. Enter or confirm:
  • Signer name and title (who signs for the vendor)
  • Owner contact — name, title, email (who signs for the customer)
Step 4 — Exhibit A Lines
Add line items:
  • Cost code (dropdown)
  • Description
  • Amount ($)
Total auto-calculates. Add as many lines as needed.
Step 5 — Review & Generate
Review all details. Click "Generate Document".
Wait for the spinner. It polls up to 30 seconds.
  • Green toast = success. Click the link to open the document.
  • Yellow toast = submitted but still processing. Check contract detail later.
  • Red toast = failed. Check flow history.

What happens when you click Generate

1. Contract record created/updated in Dataverse (dcfg_contracts)

2. Line items saved (dcfg_contract_lines)

3. Template resolved — system finds "Decades_Work_Order" template by family + type

4. Document request written to dcfg_document_requests (status: Pending)

5. Flow triggers automatically on new row

6. Flow reads contract + vendor + customer + property, builds token map, populates Word template

7. Output saved to SharePoint (DCFG_Outputs/CustomerName/Year/WorkOrder/)

8. Document request updated to Complete with output URL

Where it ends up

SharePoint: DCFG_Outputs > [Customer Name] > [Year] > WorkOrder

Contract Detail: Document link appears on the contract record

Bancroft Work Order Work Order Bancroft_Work_Order.docx
Same 5 steps as Decades Work Order
The only difference: pick a Bancroft/TPA customer at Step 1.
System auto-detects the family and picks the Bancroft template.
If the contract fee is under the blanket threshold, the system uses the Blanket template instead.

Template resolution

TPA customer + Work Order type + fee OVER threshold = Bancroft_Work_Order.docx

TPA customer + Work Order type + fee UNDER threshold = BANCROFT_BLANKET_WORKORDER_TEMPLATE.docx

Threshold set per customer in dcfg_blanket_workorders table.

Bancroft Blanket Work Order Work Order BANCROFT_BLANKET_WORKORDER_TEMPLATE.docx
Same wizard, automatic selection
You don't manually choose "blanket" — the system routes to this template when:
  • Customer is TPA (Bancroft family)
  • Contract fee is at or below the blanket dollar threshold
Same 22 fields as standard Bancroft WO. Identical user experience.

NEW CUSTOMER PROPOSALS (MSA + EXHIBITS)

Uses the New Proposal Wizard — creates an MSA record + rates + locations, then generates the full document package.

Full Proposal Package Proposal MSA + Exhibits A, B, C, D
Go to Proposals > New Proposal
Opens the 4-step Proposal Wizard. Decades family only.
Step 1 — Service Package
Pick one:
  • Package A — Essential (basic maintenance)
  • Package B — Extended (full-service + seasonal)
  • Package C — Premium (all-inclusive + specialty)
This determines which Exhibit A template is used.
Step 2 — Customer & Vendor
Customer: Search existing OR create new. Fill in:
  • Name, contact, email, phone, title
  • Signer name + title (who signs for customer)
  • Billing address (street, city, state, zip)
MSA details:
  • MSA name (auto-generates from customer name)
  • Effective date
Vendor: Pre-filled with Decades info. Enter vendor signer name + title.
Step 3 — Pricing & Locations
Pricing mode:
  • Uniform — one rate for all location types
  • Type-based — different rate per location type (e.g., office vs warehouse)
Enter monthly membership rate and onboarding fee per location (or per type).
Enter service fee %.

Locations: Add each property/location with name, type, address.
Admin locations are $0 — system zeros them automatically.
Totals calculate live: monthly total, annual membership, total onboarding, total contract value.
Step 4 — Review & Generate
Review everything. Click "Generate Proposal".

What happens in order:
  1. Customer created (if new)
  2. MSA record created in Dataverse
  3. MSA Rates created (one per location type)
  4. Template resolved by package (A/B/C)
  5. Document request submitted
  6. Flow generates the document
  7. Polls up to 90 seconds for result
Wait for the spinner. Proposal generation takes longer than WOs.

Current State vs. Future State

Today: Generates one document per request. Each exhibit is a separate flow run.

Future (Send Pipeline): Submit for approval > approver initiates > system generates ALL docs (MSA + all Exhibits) > PDF > merge > send as one package.

EXHIBITS (Generated with Proposals)

Exhibits are MSA attachments. Today each is a separate document request. Future: all generated together in one send action.

Template selected by package choice

  • Package B (Extended) → Exhibit_A_Concierge_Package_B.docx
  • Package C (Premium) → Exhibit_A_Optimized_Package_C.docx

Flow Switch case names

  • Decades_Exhibit_A_Optimized_C
Exhibit B — Location List Exhibit Exhibit_B_Location_List.docx
3 fields only
  • contract_client_name
  • property_name
  • msa_effective_date
Location rows are NOT auto-populated
Variable row count. Word Online can't populate repeating sections.

Path A: Flow fills scalar fields, user opens in Word Online and manually adds location rows.
Path B: User pastes from Excel into the Word document after generation.
Flow Switch case: Decades_Exhibit_B_Location_List
Exhibit C — Fee Schedule Exhibit Exhibit_C_Fee_Schedule.docx
7 fields — includes computed rates
  • contract_client_name
  • msa_effective_date
  • membership_qty — number of billable locations
  • membership_rate — monthly rate per location
  • onboarding_qty — number of locations being onboarded
  • onboarding_rate — one-time fee per location
  • onboarding_total — qty x rate
Rates come from dcfg_msa_rates
The flow queries dcfg_msa_rates by MSA ID to get membership and onboarding rates.
These rates were created in Step 3 of the Proposal Wizard.
Flow Switch case: Decades_Exhibit_C_Fee_Schedule
Exhibit D — Insurance Requirements Exhibit Exhibit_D_Insurance_Requirements.docx
2 fields — simplest document
  • contract_client_name
  • contract_contractor_legal_name
Flow Switch case: Decades_Exhibit_D_Insurance
This is essentially a cover page. The insurance requirements themselves are static template content.

THE ENGINE — What Happens Behind the Scenes
The DocGen v2 Flow — Every Document, Same Engine
SPA writes a row to dcfg_document_requests
Status: Pending. Contains: request type, template ID, contract/MSA ID, requested by.
Dataverse trigger fires the flow
Flow ID: ada6473f-d528-f111-8341-7ced8d709173
Trigger: "When a row is added" on dcfg_document_requests.
Flow reads the template record
Gets dcfg_name from the template — this is the Switch case value.
Flow reads source data
Depending on doc type: contract + vendor + customer + property + MSA + MSA rates.
All data gathered into a Build_Token_Map Compose action.
Switch_Template routes to the right Populate action
13 cases, one per template. Each case has a "Populate a Microsoft Word template" action.
The Populate action maps token map values → Word content controls.
Populated document saved to SharePoint
Output path: DCFG_Outputs/[Customer]/[Year]/[DocType]/
Document request updated to Complete
dcfg_status → Complete (100000002), dcfg_output_file_url → SharePoint link.
SPA picks up the URL on next poll and shows the download link.
