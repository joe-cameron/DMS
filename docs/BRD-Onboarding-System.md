# Customer Onboarding Requirements

When we sign a new provider there's a lot that has to happen before they're actually receiving service. Right now that process is managed through conversations and email and people remembering what comes next. Steps get missed. When someone asks where we are with a new customer, the answer takes three phone calls.

We need a system that gives everyone a clear view of where every onboarding stands and makes sure nothing falls through the cracks.

## What onboarding looks like

Every new customer goes through roughly the same process. First the sales team gets the proposal out and the deal signed. Then contracts get executed and work orders get issued. Then we set up accounts internally, assign vendors, get billing configured. Then the physical locations get inspected and documented. Then we verify insurance and compliance. Then we go live and monitor for a while to make sure everything is running.

That's six phases and about thirty steps total. The details change from customer to customer but the phases don't.

## What we need

When a manager starts a new onboarding case for a customer, the system should create the full checklist automatically so nothing gets skipped. Each step needs to have a name, a person responsible, a due date, and space for notes. Staff marks steps complete as they go. The system should track when each step was done and who did it.

Managers need to see all active onboarding cases in one place with a quick view of how far along each one is. When you open a customer record you should be able to see their onboarding progress right there. The dashboard should show how many active onboardings we have going.

You should be able to search by customer and filter by status — show me everything that's in progress, show me everything that's waiting on go-live, that kind of thing.

## The checklist

The standard 30-step checklist should be managed by administrators. If the onboarding process changes — we add a step or rename one — the administrator updates the template. But that change should only affect new cases going forward. Cases that are already in progress keep the checklist they started with.

## Closing a case

When everything is done and the customer is live, a manager closes the case. If a customer drops out before we finish, the case can be closed early. Closed cases should be reopenable in case something comes back up.

## General expectations

Cases should never be permanently deleted, just deactivated. Step completion should be logged. The system should track progress but not make decisions — people decide when a step is actually done. Changes to the checklist template should not change cases that are already in progress.
